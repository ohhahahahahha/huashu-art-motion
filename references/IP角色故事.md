# IP 角色故事：固定身份，按剧情生成表演

用于一二布布或用户指定 IP 的新故事，包括「笔画出角色，角色接着演」。先读本页，再用镜头表、图片接入和角色合成指南。沿用已选定的角色身份；新故事从文案与表演需求开始。

## 参考与故事素材的边界

- **身份参考**可跨故事沿用：设定图、三视图、原始 IP 图与用户确认的外形。锁轮廓、头身比、五官、耳朵、配色及身份细节。
- **表演素材**按本故事设计并生成：姿势、表情、视线、朝向、道具接触、双人互动和必要的中间帧。旧图集只帮助理解身份和画风，不能拿它有什么动作来决定新故事能演什么。
- 用户明确允许复用某个通用动作时，逐镜说明它为何准确匹配；不能因此整套沿用旧故事图集。故事新增或改动的关键动作仍需生成。

一二布布保持参考中的白色／棕色身体、腮红、耳朵、领结及短爪，以实际参考为准；不自行增加衣服、口袋、长手臂或写实手指。素材放在本次项目中，公共 Skill 不内置用户的角色图、私人文案或生图回执。

## 从故事到图集

1. **读故事，先做分镜。** 逐镜列出谁在做什么、为什么做、对方怎样反应；身份已选定就不重新设计角色。沿用 `镜头表模板.md`，每镜 2–6 秒，结尾落在人物动作上。
2. **写 `<项目>/角色动作表.md`。** 与镜头编号对应，至少有：镜头／角色／具体动作与表情／朝向、视线／道具与接触点／所需关键姿势和中间帧／素材路径／状态。状态区分待生成、待验收、可用。每个关键动作都要有准确对应的素材，不能只写「用已有图集」。
3. **按动作表调用图片工具。** 读 `images.md` 和 `10-角色.md`，使用本次会话实际可用的生成／编辑工具，把身份参考与本镜的动作要求同时传入。生成数量由剧情决定；4×2 只是一种排版，不能把所有故事都压成八个通用姿势。按相关动作分小批生成，优先修正不合格单元，不为补一个动作重做全部素材。没有图片工具或生成失败时，记录缺口并暂停依赖这些素材的镜头，不暗中换用旧故事图集。
4. **验收、切帧。** 检查身份一致、姿势可读、动作顺序、道具真的握住／递到对方手中，以及双人关系。每组动作的画布、角色比例与脚底锚点统一；切帧保留同样的边距，不能逐帧紧裁导致抖动。留存需求、工具记录与验收结果，不把文件 hash 当成身份或生成来源的证明。
5. **按剧情合成。** 用本故事素材驱动动作时间线。递伞需要伸手、接触、交接后松手；仅把一把伞贴在站立角色旁边不算完成。位移适合角色已有走路帧时移动位置，不能代替抬手、拥抱、拿取等肢体动作。双人紧密接触可生成同框序列，或用 scenes 管理遮挡、道具所有权与锚点。
6. **逐镜回查。** 对照文案、镜头表和动作表看成片：关键动作是否发生、角色是否一致、素材是否对应本故事、笔收起时是否跳姿势。缺帧就回到第 3 步补生成。文案变化时先更新动作表，再决定哪些素材需要重做；不因渲染成功就判故事演绎完成。继续走 Skill 原有 QA 和交付流程。

|---|---|---|---|---|---|---|---|
| 01 | 一二 | 撑伞等候，发现布布后抬头 | 朝右，看画外布布 | 短爪包住伞柄 | 等候→抬头→招呼 | 素材/本故事/一二_等候/ | 待生成 |

## 白板画出角色后继续表演

`y3_whiteboard` 保留原有图文白板；出现 `character` cue 或指定 `data.mode: "story"` 时进入角色故事模式。此模式每条 cue 都是一个角色或同框组合的一段表演；不会套图文清单排版、自动拉远或重复绘制旧姿势。背景、复杂道具与镜头调度需要 scenes 时直接选择 scenes，不把整部故事塞进一个长片段。

```json
{
  "grammar": "y3_whiteboard",
  "duration": 6,
  "theme": "chalk",
  "data": {"mode": "story"},
  "cues": [
    {
      "at": 0,
      "kind": "character",
      "image": "素材/本故事/双人_倾伞/000.png",
      "frames": "素材/本故事/双人_倾伞",
      "fps": 8,
      "dur": 6,
      "data": {
        "actor": "一二和布布",
        "action": "一二把伞倾向布布，两人并肩走",
        "box": [0.12, 0.1, 0.65, 0.8],
        "to": [0.2, 0.1, 0.65, 0.8],
        "reveal": 1
      }
    }
  ]
}
```

- `frames` 必填，是本故事的连续动作帧目录或路径数组；目录按文件名排序。预览页面需要路径数组，`render.py --spec` 会自动展开目录。`image` 可省略，默认揭开动作第一帧；提供时必须与动作第一帧同尺寸、同构图、同姿势，避免收笔跳变。所有帧统一画布尺寸，使用透明背景。
- `actor` 标识同一个角色／组合；`action` 写具体剧情动作。`box` 和可选 `to` 是相对 safe 内容区的 `[x,y,w,h]`，全部在 0..1 内。等比放入框；画完后用动作帧表演，同时可平移到 `to`。不填 `to` 就原地表演。不能用 `to` 的位移充当角色动作。
- `reveal` 为绘制秒数，默认 0.8；后续姿势切换通常设为 0，角色就不用每次重画。动作序列从绘制完成那一刻开始，播放完停在最后一帧；只有确实循环的动作才写 `loop: true`。
- `dur` 包含绘制和表演；省略时持续到同 actor 下一条 cue 或片尾。一个角色的片段不能重叠。一支笔不能同时画两个角色，把绘制时间错开，已有角色可以继续表演。
- 当前绘制是 **Reveal 遮罩揭开**，不宣称沿轮廓真实逐笔描线；要求真实笔顺时需另备路径并用 scenes 实现。`data.penColor` 可指定笔尖／笔帽颜色，不会把角色原图自动改成该颜色；白色线稿需准备对应素材并使用深底。

渲染前运行 `python scripts/clip_lint.py 镜01.json`；用 `render.py --spec 镜01.json --stills ...` 核对绘制中、收笔、动作中和结束姿势，再出视频。此接口播放素材，不会读取故事自动调用生图；故事拆解、生图、验收由执行 Skill 的 Agent 完成。

## y4 与角色质量规则

`y4_storytime` 适合单角色讲述、气泡和反应镜头，不把它当任意双人剧情的模板。显式指定 `data.pose` 时必须有对应帧，缺帧会启动失败并要求补生成。更复杂的连续动作使用上面的白板故事接口或 scenes。

角色仍按 `角色精细度.md` 检查。用户选定的平面 IP 以参考中的造型、平涂与短爪为准，不为通用「两层明暗／材质细节」要求擅自改成立体角色；是否合格取决于身份准确、动作具体、互动成立和全片一致。
